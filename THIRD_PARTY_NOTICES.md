## MKVToolNix artifacts

`build/tools.lock.json` pins MKVToolNix 102.0 and its complete source. Windows uses the same-version source-built CLI pair and actual DLL closure described below; the official Windows ZIP URL/hash remain historical references, never a fallback. Linux keeps the pinned official x86_64 AppImage: only its unchanged CLI executables and 22 proved-needed bundled libraries are selected. The exact hashes of all 83 omitted library/static-archive members are recorded in `build/tool-payload.lock.json`. A changed or unaccounted upstream file fails acquisition; omitted files remain unchanged in the cached AppImage. Both targets include the complete MKVToolNix source under `tools/licenses/corresponding-source`, with COPYING, README and `doc/licenses` under `tools/licenses/source-notices`. MKV processing invokes only `mkvmerge` and `mkvextract`.

MKVToolNix includes separately licensed libEBML/libMatroska/librmff (LGPL), avilib (GPL), JSON and pugixml (MIT), utf8-cpp (Boost), fmt, Qt and artwork. The verified source's actual `lib/fmt/LICENSE` is MIT-style with an optional compiled-object exception; upstream's BSD description/notice filename is not substituted for that text. Acquisition also extracts that license, three vendor LGPL texts and the source archive's Windows/AppImage/configure recipes. Complete source retains the other upstream terms.

Windows builds from the pinned release source and exact MSYS2 UCRT64 package inputs using `build/build-mkv-windows.sh`. The build disables the GUI but retains required QtCore **6.12.0**. Every actually shipped DLL is byte-matched to its pinned binary package; that package's BUILDINFO recipe hash must match its complete collected source package's PKGBUILD. `tools/licenses/mkv-source-build` contains the full source packages (including upstream archives/downstream patches), original binary metadata/notices, MSYS2 recipe-snapshot BSD3 notice, controlling scripts, actual configuration/compiler observations and the hashed worker/material receipt. GMP, ICU and libvorbis binary packages omit notices; their exact primary texts are extracted from authenticated nested source archives. ICU 78.3's actual Unicode V3/third-party notice is retained, not replaced by an older ICU text. Core's GPL2 alternative and GMP's GPL2-or-later alternative at GPL2 are selected alongside the GPL2 worker. Other Qt modules' package-wide declarations are not substituted for Core's actual terms. GCC runtime exceptions, winpthreads and any LGPL library terms remain component-specific. The historical official Windows workers' static Qt 6.10.2/MXE gap is not claimed solved for those old binaries; the replacement ships its own bound materials.

The unchanged Linux CLI closure retains QtCore **6.6.1** and the other 21 required libraries. VirtualKeyboard, unused Qt modules and three static Boost archives are excluded. Fifteen retained shared libraries match primary AlmaLinux binary RPM members byte-for-byte; SourceRPM headers bind 13 complete source RPMs with upstream archives, patches and build specifications. Actual binary-RPM notices are included. QtCore and all three ICU libraries match the official Qt 6.6.1 SDK bytes. Complete QtBase source, actual SDK qconfig and primary module/runtime terms are collected. `build/tool-materials.lock.json` binds these relationships; included sources live under `tools/licenses/corresponding-source`, notices/configuration under `tools/licenses/upstream-terms`. Core's GPL2 alternative is selected alongside the GPL2 worker. The SDK Enterprise label is not a commercial-only source restriction. No additional missing Linux Core source/build or relink artifact was identified. Public distribution must still deliver the applicable collected source/materials and notices on both targets; see the [closure record](docs/verification/release-distribution-closure.md).

The exact texts remain the primary record. Running a separate executable does not remove its redistribution obligations, automatically assign its license to the C# code, or settle whether a particular combination is an aggregate. [The original-code license decision](docs/license-decision.md) keeps that question separate from the selected MIT terms.

## FFmpeg artifacts

`build/ffmpeg.lock.json` pins the complete FFmpeg source snapshot `2a571b606854520cf89804d8030c8b328e621689` and zlib 1.3.2 source by SHA256. `build/build-ffmpeg.sh` builds only `ffmpeg` and `ffprobe` with explicit built-in capabilities and static zlib, disabling automatic dependency detection and networking. No optional external codec/hardware libraries or `ffplay` are shipped. Acquisition and inventory reject GPL, version3 and nonfree configuration; this build is LGPL-2.1-or-later. This does not assign that license to original TrackTrim code.

The package includes both complete source archives, applicable source/license texts, the local build recipe, configure arguments/output/generated configuration and an actual build receipt. The receipt binds the recipe/source/zlib hashes, the complete worker/material set, actual compiler/target/runtime macro observations, make/NASM and worker SHA256 values. The verified cache cannot substitute another worker name, changed bytes or missing materials. GCC Runtime Library Exception 3.1, GPL3 and complete applicable MinGW runtime notices are collected separately; those exceptions/permissive terms are not treated as a requirement for every historical compiler source. The build can run natively on the corresponding CI platform; local Linux-to-Windows cross-build proof has its own actual compiler receipt.

Only OS runtime dependencies are allowed: Windows OS/UCRT/API-set DLLs, or Linux glibc's loader/libc/libm/libmvec/libgcc as actually observed. Both builds link the same pinned zlib source statically. Actual PE imports/`ldd` evidence is recorded and a new undeclared dependency fails acquisition. Existing packaged MKV/MP4 execution, relocation and the clean Linux container check remain mandatory. Local source-build and encoded-packet proofs are described separately in the [closure record](docs/verification/release-distribution-closure.md).
