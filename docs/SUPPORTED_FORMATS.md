# Supported formats and preservation

The current runtime backend is MKVToolNix 102.0, using `mkvmerge` and same-version `mkvextract`. The identification parser accepts format version **20**, established from the pinned executable's JSON, and rejects a different format version. MP4 production processing is not implemented. File extension alone does not establish MKV support; the backend identifies the actual local regular file and rejects unsupported detected cases before writing output.

The supported subset is ordinary self-contained Matroska with video/audio/subtitle tracks, ordinary chapters, supported user tags, and attachments. This matrix describes implemented per-job checks and fixture limits; executed platform/fixture evidence is recorded in `PLAN.md`. A supported check does not imply coverage of every codec or metadata variant.

| Feature | Supported/retained | Inspected / per-job check | Integration evidence and limits |
| --- | --- | --- | --- |
| Encoded video | Every video track retained; video removal forbidden | Approved retained mapping, order, codec/known properties and metadata | Retained VP8 and direct FFmpeg-origin H264 payload comparisons are fixture checks; routine probing is not packet proof. |
| Audio/subtitles | Explicit Keep selection; all subtitles may be removed; zero audio requires confirmation | File-local backend IDs, retained order and effective flags; explicit empty-selection CLI options | Distinguishable same-metadata PCM audio and direct FFmpeg-origin AAC fixtures check exact retention. Retained SRT payload comparison also covers zero-audio output. |
| Track title/languages/flags | Preserve inspected original values and effective supported flags | Compare mapping and expected metadata using the shared explicit ISO alias policy below; documented defaults remain distinct from unknown | Bibliographic/terminologic language aliases are compared consistently across tracks, chapters and tags. Tags do not prove spoken language or promise player selection. |
| Container title | Preserve | Compare identified value | Writing application/layout/SegmentUID may change as documented below. |
| Ordinary chapters | Preserve supported semantic content | Extract same-version chapter XML, securely parse and compare semantic content | Counts/simplified text alone are insufficient; advanced/reference changes require rejection. |
| User tags | Preserve global and retained-track targets; removed-track tags need deliberate policy | Extract and compare semantic XML against the retained mapping | Do not ignore arbitrary UID-target mismatch or claim all private metadata preserved. |
| Attachments | Retain supported attachments including fonts/artwork after subtitle removal | Compare order, UID, name, description, MIME type, and size | Fixture payload comparison uses a text attachment; actual font/artwork payload and legacy font MIME variants remain unverified. Per-job metadata does not prove attachment byte equality. Extraction uses app-owned paths. |
| Duration/timing | Expectations relate to retained content | Extract every retained track's `timestamps_v2`; compare actual frame count/timestamps and the extractor's synthetic terminal boundary with a **1 ms** tolerance for Matroska tick rounding, plus known default-duration properties and the narrow AAC-LC policy below | No total-container-duration equality requirement: deleting the longest track may legitimately shorten the container. Per-job checks do not independently parse every packet's BlockDuration. Timestamp equality does not establish encoded payload equality. |

## Deliberate container differences

Whole-container byte equality is not expected. Remuxing changes file layout, indexes, writing application, track numbers, and index-entry counts. The adapter permits track UID remapping only for a source identified as written by MakeMKV; other sources retain UIDs. Its retained input/output mapping is explicit by approved order, known codec properties, metadata, effective flags, and timing, rather than a language/codec pair alone. Tag TrackUID references use that map; unsupported chapter references are rejected.

`--track-order`, explicit retention/flags, `--normalize-language-ietf off`, and `--disable-track-statistics-tags` define the command policy. Existing statistics tags remain part of checked tag XML; new statistics are not generated. Some MKVToolNix-generated statistics properties disappear under that policy: an input with such properties can fail strict verification and remain unpublished. The Phase 2A fixture permutation disables creation of those tags, matching the original fixture generator; batch processing does not relax their checks. SegmentUID/container layout are not a retained-content identity oracle.

Track, chapter and tag comparisons share a platform-independent table of registered ISO 639-2 bibliographic/terminologic and ISO 639-1 aliases from the [Library of Congress registry](https://www.loc.gov/standards/iso639-2/ISO-639-2_utf-8.txt). For example, `ger`/`deu`/`de` and `fre`/`fra`/`fr` are equivalent in comparison copies. Original metadata is not rewritten by a culture lookup. An absent IETF field may be added only as an equivalent registered plain code. Existing regional/script/private suffixes and unknown language values remain exact; no base-language collapse or `CultureInfo` inference is used.

An absent AAC `DefaultDuration` may be added only when unchanged, bounded AudioSpecificConfig proves ordinary **AAC-LC object type 2**, 1024 samples per frame, a supported explicit sampling-frequency index matching the unchanged track rate, supported channel configuration and zero general-audio extension flags. Zero padding or the recognized SBR-disabled sync extension is accepted; ambiguous configurations do not qualify. The added integer duration must equal `1024 × 1,000,000,000 / sample rate` within **1 ns** of integer rounding. This exception does not cover HE-AAC, 960-sample frames, changed codec configuration/rate, or an already known duration that changes or disappears. All other compared known properties remain strict. Every retained frame's timestamp/count is still verified independently; accepting an inferred header cannot excuse a shifted AAC stream.

Pinned `mkvextract` writes all actual frame timestamps followed by one synthetic `last timestamp + duration` boundary (`src/extract/tracks.cpp`, `close_timestamp_files`, lines 136–147 in the [pinned 102.0 source archive](https://mkvtoolnix.download/sources/mkvtoolnix-102.0.tar.xz)). Only when the source boundary exactly duplicates its last frame timestamp and the AAC missing-duration addition passes the rule above may the candidate boundary equal its last frame plus that derived duration, within the same 1 ms quantization tolerance. Actual frame values/count are still checked; known terminal boundaries and all other codecs remain strict. The direct FFmpeg 7.1.1 fixture exercises this supported case. The direct FFmpeg 9.0.2 fixture has a known 16 ms final AAC duration that remuxes to about 21.333 ms; verification deliberately rejects that change. This is not general AAC compatibility.

## Rejected or outside the checked subset

Detected segment families and next/previous segment links, ordered chapters, chapter segment/edition/track/process references, uncommon track types, and tag records with multiple TrackUID targets, mixed track/non-track targets, or dangling nonzero TrackUIDs are rejected. The parser also rejects known advanced luminance/chromaticity/white-point fields, HDR/Dolby Vision properties exposed by identification, and PQ/HLG transfer characteristics. These are concrete property checks, not restrictions inferred from a codec or filename. An identification warning is a preflight failure.

Pinned identification JSON does not expose `SegmentFamily`, so a narrow BCL-only reader independently visits the actual EBML Segment/Info children and rejects `SegmentFamily`, `PrevUID` and `NextUID` element IDs. It seeks past finite media payloads rather than searching arbitrary bytes or decoding clusters; `mkvinfo` is not a production dependency. Exactly one bounded Info is required. A Segment may have an unknown size bounded by EOF, but unknown-sized children/clusters, duplicate Info, multiple/nested Segments, malformed/out-of-parent lengths, unrecognized trailing data, or more than **100,000 element headers** produce a localized unsupported-structure error before processing. The reader uses the same read-only regular-file handle checks as source inspection; Linux `O_NONBLOCK | O_NOFOLLOW` plus `fstat` rejects a substituted FIFO without blocking. This is a bounded linkage check, not a general EBML validator.

Unknown optional fields can be ignored only if they cannot weaken a required capability check. The current probe cannot enumerate every unknown/private Matroska element or prove that all Dolby Vision/HDR metadata is detectable; no universal container fidelity claim is made. Ordinary SDR fixture coverage does not prove HDR preservation.

## Phase 2 input discovery scope

The desktop accepts several explicitly selected MKV files or one local folder per addition. Immediate entries are the default. Phase 2D1 optionally includes subfolders, sharing a 10,000-examined-entry budget across all visited directories and a 100-entry session/addition limit including visible failures. Traversal is limited to 32 nested directories and never follows directory symlinks/junctions/reparse points. The complete local-directory policy is applied before every non-excluded enumeration, including rejection of ordinary network-mounted children without reparse flags. Limits, redirected-directory encounters, traversal failures or cancellation before acceptance add no partial subset. Cancellation during subsequent inspection retains accepted rows. Duplicate canonical paths/file identities are collapsed; the first accepted row retains its provenance, destination and approval. Missing/unreadable/nonregular candidates remain visible. Each accepted file still requires real inspection and its own manual selection/approval; a suffix is not container evidence. Spaces/Unicode and native filename rules use the existing local-path policy.

Recursive input requires a selected existing output root, rejects a root equal to or above the source tree, and excludes a descendant output subtree plus actual known application data/owned working locations. Folder outputs preserve validated relative parents without the source-root name: `Series/Season 2/episode.mkv` -> `Output/Season 2/episode.trimmed.mkv`. Explicit files keep flat naming. Review is creation-free; only execution may prepare missing directories beneath the captured explicit root. Existing files, source aliases, duplicate destinations and redirected ancestors remain errors. Cleanup removes only owned job artifacts; empty prepared output directories may remain after failure/cancellation. This expands discovery/destination handling, not the supported media/container subset.

MP4, playlists, URLs, external subtitle editing, transcoding, playback, source replacement, title-only/regex rules, other forced-filter modes, preset overwrite/update and import/export, and automatic execution/byte-offset restoration remain outside this implementation. Native Wayland and arbitrary Linux distributions are separate acceptance targets.

Unfinished queue listings can be restored explicitly from the portable versioned record. They retain paths, inclusion and folder-relative destination intent, not media inspections, selections, approvals or job authority. Restored rows require fresh inspection and explicit plans/Review; missing or changed sources and existing outputs retain the ordinary error behavior. Discard/New batch never delete media or ownership records. Corrupt records and concurrent writes are reported separately from media ownership. See the [bounded storage contract](ARCHITECTURE.md#unfinished-queue-list-recovery).

## Language-selection rules

Phase 2B1 optionally proposes Keep choices for independently inspected batch files. Audio and subtitles each default to unchanged. A targeted category keeps **every** exact match; it never prefers the first/default/highest-channel track. All video and the existing attachment/metadata contract are retained. Apply changes selections only; plans still require explicit per-file approval and aggregate Review.

Phase 2B2 adds one optional literal title-contains constraint per targeted category, disabled by default. A track must satisfy **both** its language predicate and that title predicate. Search text is trimmed at its edges, then compared with the actual inspected track `Title` using .NET `StringComparison.OrdinalIgnoreCase`; Latin/Cyrillic case handling is culture-independent. Internal whitespace and punctuation remain literal. Null/blank titles do not match, and filenames, codec labels and UI fallbacks such as “Untitled” are never searched. An enabled empty/whitespace-only constraint is invalid and leaves the whole file unchanged with a localized explanation. Disabled title constraints preserve language-only behavior; an unchanged category ignores its stored title settings. There is no title-only, regex, wildcard, transliteration, fuzzy or ranked matching.

Matching supports registered ISO 639-1 / 639-2/B / 639-2/T aliases from the shared frozen table. Supported tags have the narrow grammar `primary[-Script][-REGION]`: a known two/three-letter primary, optional four-ASCII-letter script, then optional two-ASCII-letter or three-digit region. Script/region shapes are validated, not their IANA registration. Matching is case-insensitive after primary alias normalization and compares the **entire** tag: `ger` = `de`, `fre` = `fr`, `ru` differs from `ru-RU`, and `sr-Latn` differs from `sr-Cyrl`. Other BCP 47 variants/extensions are outside this slice and require manual selection.

A targeted track needs a known plain legacy language, even when its title does not match. When IETF metadata exists, its supported full tag is authoritative only if its primary agrees with that legacy alias. Missing/unregistered/private-use languages, `und`, `mul`, `mis`, `zxx`, malformed/unsupported tags and conflicting fields produce visible manual-review reasons. Any such issue, or zero combined audio matches in an input containing audio, leaves **all choices for that file** unchanged. Already silent inputs remain valid. No combined subtitle matches may propose keeping none and is explicitly reported. Untargeted categories are preserved without interpreting their language metadata.

Normalization is comparison-only: no tags, titles, ordering, flags or original metadata are rewritten, and preservation verification is not relaxed. Language metadata does not prove the language actually spoken. Preview is read-only and bound to the live list, inspection, selection and destination revision; only explicit Apply can edit choices. Excluded/completed items remain untouched. New additions/reinspections require another preview/application, and New batch clears transient proposals.

Phase 2B3 optionally adds **Keep only forced subtitles** to subtitle KeepMatching: language AND optional literal title AND (`forced-only` off OR inspected `IsForced`). It defaults off and is ignored when subtitles are unchanged; audio/video are unaffected. The existing adapter uses Matroska's `false` default only when `forced_track` is absent; malformed values still fail inspection. Every targeted subtitle language is validated, even on non-forced or title-nonmatching tracks. No valid combined matches explicitly proposes none. Every matching whole track is retained in original relative order with its original flags/metadata; titles, default flags, filenames and subtitle text/events never establish forced status. The filter does not extract forced events from a mixed track or promise how players display it. Configuration edits clear only the proposal; existing explicit application, approval and ownership rules remain in force.

## Portable rule presets

Phase 2C1 stores only the existing language/title/forced-subtitle configuration, including inactive values. Presets do not expand supported containers, matching modes or preservation guarantees. Selection alone does not load; explicit Load changes only configuration and requires a fresh Preview if values differ. Manual selections, approvals and aggregate Review are preserved until actual Apply changes choices. Names and original rule values are not translated or canonicalized for storage. The [bounded catalog contract](ARCHITECTURE.md#phase-2c1-portable-rule-presets) defines validation, portable location and failure behavior. No source/destination, track ID, queue, ownership or UI-language state is serialized.

## Platform and native requirements

Archives target Windows 11 x64 25H2 and Ubuntu 24.04 x64 Desktop with X11/XWayland. Tested hosts/builds and missing acceptance are listed in `PLAN.md`. Avalonia classifies Ubuntu 24.x as Tier 2; upstream support is not this application's acceptance evidence. [Avalonia platform requirements](https://docs.avaloniaui.net/docs/supported-platforms).

Self-contained .NET includes the runtime but relies on OS native libraries. Ubuntu 24.04 baseline dependencies include glibc, libgcc/libstdc++, zlib, OpenSSL, ICU 74, Kerberos/GSSAPI, Brotli, GMP (`libgmp10`), CA certificates, tzdata, and the X11/ICE/SM/fontconfig/OpenGL libraries used by Avalonia. Static inspection of the pinned AppImage CLI closure found GMP outside the bundle; Qt6Core and its GLib/ICU 56 dependencies are provided in the extracted tree. This static dependency inspection is separate from Linux runtime acceptance. The exact runtime library resolution is captured in `native-dependencies.txt` inside each Linux package. CI records exact installed versions for its native-libraries-only container; users must not install .NET or media tools to complete the intended desktop workflow. [Microsoft Ubuntu dependencies](https://learn.microsoft.com/en-us/dotnet/core/install/linux-ubuntu-install?pivots=os-linux-ubuntu-2404&tabs=dotnet10).

The Linux tool bundle retains the extracted upstream AppImage library tree and both native CLI executables, rather than copying a single `mkvmerge` binary. The production backend launches `tools/app-root/usr/bin/mkvmerge`/`mkvextract` directly and supplies the packaged library search path through `ProcessStartInfo.Environment`. Fixed shell wrappers are build-time acquisition/fixture helpers only. Qt is required even for MKVToolNix CLI programs. The package scan checks application native assets and the CLI executables' actual transitive `ldd` closure; retained unused GUI libraries are not standalone runtime requirements. Extraction is a build operation, and FUSE is not used when running the resulting package. [MKVToolNix requirements](https://mkvtoolnix.download/doc/README.md), [AppImage extraction guidance](https://docs.appimage.org/user-guide/troubleshooting/fuse.html).

The complete normal .NET publish output includes `libcoreclrtraceptprovider.so`, an optional LTTng diagnostics provider. The pinned [.NET 10.0.13 initialization code](https://github.com/dotnet/runtime/blob/v10.0.13/src/coreclr/pal/src/misc/tracepointprovider.cpp#L109-L114) permits this provider to fail loading when tracing dependencies are absent. The native scan retains the file and explicitly reports an unavailable `liblttng-ust.so.0`; only that exact missing dependency for that exact provider is optional. Missing application, runtime execution, or media-tool dependencies still fail packaging. LTTng tracing is not an application feature or a portable acceptance requirement.
