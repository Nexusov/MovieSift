# Portable distribution inventory and material gaps

**Scope: Phase 0/1; redistribution readiness remains blocked.** This audit accounts for actual Windows/Linux portable contents, distinguishes known provenance from unresolved source/build facts, and prepares the original-code license decision. It does not change application behavior, tool/dependency pins, native acceptance, or the protected-main policy. No binary release or operative application license is produced.

## Reproducible evidence

Run the existing `build/package.ps1` on each matching OS with its real fixture. The existing required Windows/Linux CI jobs perform the same packaging, packaged workflow, relocation and Linux no-SDK container checks. They additionally run `python -m unittest discover -s build/tests -v`. A missing input or mismatched material is a failure, not an unresolved-item skip.

Each `test-evidence-<RID>` CI artifact includes `distribution-reports/<RID>/`:

| File | Evidence |
| --- | --- |
| `distribution-<RID>.json` | Actual Git checkout/tree/parents and dirty state; RID; final archive name, byte size and SHA256; every shipped path/size/hash; component matches, applicable native observations, and explicit unresolved items. |
| `package-SHA256SUMS.txt` | The existing full package manifest. The report separately accounts for the manifest itself, which cannot hash itself. |
| `build-provenance.json`, `tool-provenance.json` | Actual SDK/runtime/build platform and pinned tool/source URLs/hashes. |
| `nuget-inventory.json` | Restored metadata, publisher repository commits, copied notice files, and exact supplemental text provenance. This is not a substitute for actual file inventory. |
| `tool-file-provenance.json`, `upstream-materials.json` | Every retained tool/material's actual hash and acquisition origin; exact supplemental terms/header URLs and hashes. |

No executable, portable archive, large source tarball, original NuGet archive or private-path `project.assets.json` is uploaded. Reports use package-relative paths. The final archive is retained only on its builder; its identity is recorded in the report. CI artifacts expire after seven days under the existing policy; the scripts, pinned evidence profiles and this gap record remain in Git.

The report first requires exact `SHA256SUMS` coverage and compares actual ZIP/tar members with staging. Root payloads are matched by name, size and SHA256 to members of the original signed `.nupkg`, whose archive SHA512 must match its cache sidecar. Copied ordinary licenses/nuspecs must also match original members; supplemental texts must match pinned SHA256 and the package's declared repository commit. NuGet's signature-independent restore content hash is retained separately from signed-archive SHA512; these values are not interchangeable.

The report distinguishes original/generated TrackTrim output, self-contained runtime, other managed/native payloads and distributed symbols, bundled executables/libraries/static archives, source archives, documentation/assets/notices, metadata-only restored packages and build-only tools. Every unmatched payload remains an explicit unknown. `TrackTrim.exe`/`TrackTrim` is a generated .NET apphost, not an assertion that the SDK's native template is original C# code. A dependency's presence in a notice roll-up alone does not establish that it was compiled.

## Available source/build material and exact open gaps

The [pinned source archive](https://mkvtoolnix.download/sources/mkvtoolnix-102.0.tar.xz) includes the project's sources, bundled fallback libraries, license/copyright headers and build recipes. Windows's recipe follows moving MXE inputs; AppImage's recipe references Qt `latest`, a moving AppImage helper, installed distro packages and a local Boost prefix. Generic build recipes are useful materials, not the exact published build configuration.

The [annotated release tag](https://codeberg.org/api/v1/repos/mbunkus/mkvtoolnix/git/tags/b583693c2d8d8b0f7342e523dcc9efea924dd964) resolves to `e85150f7e615f9f735f2187d48e808dc56adfe01`, also recorded by [Windows build 17027](https://buildbot.mkvtoolnix.download/api/v2/builds/17027/properties) and [AppImage build 17029](https://buildbot.mkvtoolnix.download/api/v2/builds/17029/properties). This supports release-source provenance but does not bind the locked binary hashes to the full build closure. Public step metadata references additional build helpers; queried log-content endpoints returned no content despite nonzero line metadata. The required helper/configuration/dependency receipts were not obtained. Current MXE recipes and similarly named upstream tarballs are not substituted for them.
