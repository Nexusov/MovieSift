# TrackTrim

TrackTrim is a portable Windows/Linux desktop application for removing selected embedded audio and subtitle tracks from local MKV and supported MP4 files without re-encoding. It writes a separate file in the input container; originals remain on disk. Published per-file results report the measured source/output size difference when both lengths are known, including larger or equal-sized results. Creating a trimmed copy does not free the original's space.

The proposed **0.1.0-rc.1** review candidate is followed by the unified selection workspace and its bounded Soft-inspired Desktop redesign; no public release or tag is published. MP4 admits ordinary self-contained nonfragmented H.264/AAC/mov_text, ordinary chapters (at most one referenced QuickTime chapter track; admitted Nero data must agree), and JPEG/PNG artwork within the [preservation matrix](docs/SUPPORTED_FORMATS.md#mp4-preservation-contract). Several media tracks may reference that same chapter track; distinct chapter lists are rejected before work. [Release notes](docs/release-notes.md), [acceptance/evidence](docs/PLAN.md) and the [finite release checklist](docs/release-checklist.md) distinguish verified behavior, unavailable target desktops and specific distribution requirements. CI uploads compact test/provenance evidence, not binary release assets.

The application uses C#/.NET 10, Avalonia 12 with Fluent controls, CommunityToolkit.Mvvm, pinned MKVToolNix for MKV and pinned FFmpeg/ffprobe for MP4. English is the initial language, including on a Russian OS. The English / Русский selector in **Appearance & language** changes application text without discarding the current selection; the choice is saved beside the application.

## Unified selection workspace

One file, several files and folders use the same workspace and sequential job pipeline. The compact file area sits beside the aggregate tracks, becoming a collapsible shelf at narrow widths. File names are primary, parent/relative context disambiguates them, and full paths remain available in details/tooltips. Direct **Add files** and **Add folder** actions remain available; dropping local files uses the same bounded discovery and inspection pipeline. Folder drops are not supported. File details, advanced rules/presets and appearance are subordinate panels; opening them does not change aggregate scope.

1. Add inputs and choose an output folder. **Include subfolders** in the folder/queue options (⋯) defaults off and affects subsequent folder additions only. If recursion needs an output root, Add folder first prompts for it before choosing/scanning the source folder. Cancelling that choice scans nothing. A session holds at most **100** entries, including failures; a complete scan examines at most **10,000** entries at depth at most **32**. Directory symlinks/junctions and network filesystems are rejected before enumeration. A scan failure/limit/cancellation before acceptance adds no partial subset; cancellation during subsequent inspection retains accepted rows.
2. Inspect the aggregate track list. It shows the **union** across all included inspected files, including a language present in only one episode. Each group shows distinct-file coverage separately from occurrence count, and exposes every concrete member. Checked means Keep; checked switches to remove all editable members, while unchecked or mixed switches to keep all. Individual members and per-file details allow exceptions. Video remains retained; completed results are historical and locked. Pending/failed included inspections remain visible and block Review.
3. Use **Review changes** to open structured per-file rows. This explicit action builds independent immutable plans from each source's actual inspection, current local IDs, destination and applicable confirmation. Rows show retained/removed tracks, actual destinations, default-audio warnings, NoChange and actionable validation errors. Confirm zero audio separately for every affected file, then review again. Unresolved included files must be corrected or explicitly excluded. Ordinary files need no separate approval click.
4. Use the separate **Create N copies** action in Review; reviewing never starts processing. Review and Run occupy different controls, and opening Review focuses inert heading text so repeated keyboard activation cannot turn into Run. An all-NoChange review offers **Finish without copies**. One job runs at a time through the established verification/publication lifecycle. A NoChange item creates no copy and launches no remux. Existing files, source aliases and duplicate destinations are errors; there is no overwrite or automatic renaming. Names remain `<source>.trimmed.mkv` or `<source>.trimmed.mp4` in the original container. Folder-derived inputs preserve relative parents without adding the selected source-root name; explicit picker inputs remain flat.
5. **Pause after current file** lets that job finish. **Cancel batch** cancels its owned job and prevents the next item starting. Warnings, failures, cancellation or cleanup problems pause the queue. Resolve the warning or correct/exclude an unsuccessful item, then explicitly Review and start the remaining work. Published outputs remain intact; uncertain termination/cleanup blocks further work. MKV warnings retain explicit publish/discard and close decisions; FFmpeg failures/unrecognized warnings cannot be overridden.
6. **New queue** in the folder/queue options explicitly clears a safe in-memory list after confirmation, retaining files, settings, language, output folder and rule configuration. Sources can be added again with all 100 slots available and need fresh inspection/Review. Active work and unresolved warning/ownership/cleanup prevent reset. Inspect-pending, pause/cancel and recovery maintenance controls appear in their applicable contexts; unresolved warnings and cleanup/publication uncertainty remain persistent and actionable.

Grouping uses kind, exact canonical language, trimmed case-sensitive title, codec, audio channels, forced status and semantic commentary/accessibility dispositions. Regional/script distinctions and meaningful title text remain distinct. Collapsed rows and checkbox accessible names include forced/semantic roles and codec/channel information. Default/enabled summaries show when member values vary; original flags remain visible in expanded members and are never rewritten by Keep changes. Groups describe matching metadata, **not identical encoded content or the same dubbing performance**. Unknown/conflicting language stays explicitly unknown and separately editable; duplicate occurrences are never paired or discarded. Adding/reinspecting a file starts its tracks kept rather than inheriting an earlier group removal, so the group may become mixed. Actual edits invalidate only affected approvals and aggregate Review; no-op edits and language switching preserve them.

Advanced language/title/forced rules and portable presets remain available. Their explicit Preview/Apply changes the same per-file selections shown by the aggregate list; neither operation approves or runs work. The historical native receipts below belong to their identified binaries and do not establish acceptance of this new interface. Manual native/visual/scaling and recording campaigns remain deferred.

### Appearance

**Appearance & language** offers System/Light/Dark, curated accents, an official Avalonia color picker and HEX entry, separate light/dark page/surface/text/border overrides, reset and reduced motion. Invalid HEX or insufficient contrast leaves the last usable palette active. Color validation uses linearized-sRGB contrast, targeting 4.5:1 for ordinary text and 3:1 for essential indicators. Theme, language and motion edits do not change Keep choices, review authority or active work.

Cosmetic preferences use the separate version-1 `data/appearance.json` (64 KiB, depth 8), so saving the language cannot erase them. Missing data uses built-ins; malformed/incompatible data stays untouched until an explicit appearance reset. Writes are coalesced and atomically replace a complete bounded record under interprocess exclusion. A save failure leaves the valid appearance active for the session with a visible persistence warning; it does not independently block media execution. Reduced motion suppresses the new cosmetic effects. System follows the Windows animation preference when available and falls back to reduced motion otherwise. A newly pending warning/cleanup decision closes settings to expose its existing actions; reopening settings retains a pending-decision notice. [Headless render evidence](docs/verification/soft-workspace-evidence.json) is not native visual/scaling or clean target-desktop acceptance.

[Recursive-folder verification](docs/verification/phase-2d-recursive-folders-evidence.json) records the required real-media case and an owner-assisted Windows 10 portable GUI run: two same-named episodes published into separate season directories, with independently compared retained payloads and unchanged originals. UIA functional observations do not establish appearance, checkbox ToggleState, scaling or clean target-desktop acceptance.

Missing season output directories are validated without creation during discovery, planning and Review. Only execution prepares them under the explicit existing output root, before candidate reservation; paths and collisions are rechecked before work/publication. Cancellation/failure still cleans owned candidates and journals, but may leave newly created empty output directories. Manual destinations outside that root retain the ordinary existing-parent requirement. Selecting another shared output folder re-derives eligible unfinished destinations and requires fresh approval; completed outputs stay intact. The recursion option is not part of rule presets.

The live queue and job authority remain in memory. Its unfinished listing is checkpointed in `data/queue-list.json`: source paths, intended destinations, inclusion and folder provenance only. After restart, explicitly **Restore saved list** or **Discard saved list**. Restore never starts inspection or jobs; freshly inspect every included source, choose tracks again and perform explicit Review to create fresh independent plans. Old track IDs, selections, zero-audio consent and approvals are never trusted. Completed/no-change and actually published results are omitted; if a crash precedes the next checkpoint, existing-output collision checks still prevent overwrite.

Discard changes only saved listing data. **New queue** clears the current list and checkpoints that empty intent while retaining preferences/presets and all files. Closing awaits pending checkpoints and the existing owned-job shutdown/warning decision. Ownership journals alone govern interrupted candidates: a restored queue cannot publish, delete or terminate an old candidate/worker.

The queue record has schema version 1, a 64 KiB actual UTF-8 budget, depth 16, at most 100 entries and 4096 UTF-16 code units per path field. Cross-instance revision checks return conflict instead of last-writer-wins replacement. Invalid/incompatible data stays unchanged with a visible error; queue-write failures remain distinct from ownership failures and leave manual work available, with restart recovery explicitly unconfirmed. Correct the record externally and use **Reload saved list** with an empty current batch. No automatic retry, queue execution restoration or byte-offset resume is provided. [Phase 2 completion evidence](docs/verification/phase-2-completion-evidence.json) separates controlled persistence tests, real restored-media processing and the owner-assisted Windows 10 native restart/Restore observation.

### Explicit language and title rules

In the advanced rules, audio and subtitles each default to **leave current choices unchanged**. Enable a category and enter comma-separated language codes, then **Preview choices**. Every file shows its own retained/removed tracks, original metadata and manual-review reasons. Every matching track is retained, including multiple tracks in one language. **Apply preview** changes Keep choices only; inspect/edit choices and perform the explicit Review before Run.

Supported ISO aliases match canonically, while complete script/region tags match exactly: `eng` matches `en`, but `ru` does not match `ru-RU`. Unknown, unsupported or conflicting targeted metadata, or no audio matches, leaves that whole file unchanged for manual review. No subtitle matches may keep no subtitles and is explicitly shown. See the [precise matching contract](docs/SUPPORTED_FORMATS.md#language-selection-rules) for supported tag syntax. Metadata is not proof of the language spoken.

Each enabled category can additionally require **title contains**. This constraint defaults off and keeps every track matching **both** language and literal title text. Surrounding search whitespace is trimmed; comparison is culture-independent and case-insensitive (`OrdinalIgnoreCase`). Only the actual inspected track title is searched: missing/blank titles do not match, and neither filenames nor display fallbacks are used. An enabled blank search is invalid. Punctuation is literal, including `[]`, `.*` and `?`; there are no regexes or wildcards. Language uncertainty and zero-audio safeguards still apply to the whole file.

Preview never edits selections or approvals. Relevant batch edits make it stale; only actual applied changes invalidate affected approvals and aggregate Review. Excluded/completed items remain unchanged. Rules do not approve, exclude or run unresolved files, and never apply automatically to later additions/reinspections. Language switching preserves the configuration and valid proposal; New queue clears transient proposals. Active work and unresolved ownership block preview/application through the existing gates.

For matching subtitles, **Keep only forced subtitles** optionally also requires the inspected track's effective forced flag. It defaults off; unchanged subtitle mode ignores the stored setting. Language, optional title and forced predicates are combined, retaining every matching whole track in its original order. Titles such as “Forced” and individual subtitle events are not interpreted. Uncertain language on any targeted subtitle still requires manual review; no combined matches explicitly proposes no subtitles. Audio, video and retained metadata are unchanged. Changing the setting clears only the proposal; explicit Preview/Apply and fresh approvals are still required after actual selection changes. Player selection/display is not guaranteed.

The native sequence has an explicit automation protocol deviation (unintended aggregate Review), so it is not a clean pass of the prescribed no-Review scenario. Earlier evidence retains its original binary/platform; visual and target-desktop acceptance remain open.

### Named portable rule presets

**Save as new** stores the current audio/subtitle rule settings, including inactive language/title values and forced-only. Select a saved name, then explicitly **Load** it; selection alone changes no rules. Loading different values clears only the transient Preview, preserving actual Keep choices, plans, destinations and Review. Identical values preserve a valid Preview. Rename and confirmed Delete affect only the catalog; deleting loaded values leaves them in the editor. Startup restores the list without selecting/loading anything, and New queue keeps the catalog and rule configuration.

Presets live in `data/rule-presets.json` beside the portable application. They contain no media paths, output folder, track IDs, selections, approvals, jobs, queue or interface language. Names are trimmed, unique without case, and limited to 80 characters without control characters. The versioned catalog is bounded by 64 KiB and 100 entries; corrupt/incompatible files remain untouched with a visible error, while manual rules remain usable. Writes use fail-fast interprocess exclusion and complete-file validation. See [storage bounds and failure behavior](docs/ARCHITECTURE.md#phase-2c1-portable-rule-presets) and the [feature evidence](docs/verification/phase-2c-rule-presets-evidence.json). No overwrite/update, import/export or automatic preset application is provided.

Do not use the application as a universal preservation tool. The [supported preservation matrix](docs/SUPPORTED_FORMATS.md) defines the inspected, verified, and rejected cases. Title-only/regex rules, other forced-filter modes, preset update/import/export, automatic retries/live job restoration, playback and source replacement remain outside this implementation.

Preflight supplements MKVToolNix identification with bounded, read-only Segment Info inspection. Detected segment families and previous/next links are rejected before processing; layouts that cannot be inspected within those bounds fail explicitly. This check uses no additional media executable.

## Build and run

Install the exact stable SDK in `global.json`, PowerShell 7, and Python 3 for the build scripts (Python 3.9+ with standard-library `tarfile`/XZ support; the local verification used Python 3.13.0). Python extracts pinned source notices and generates original fixtures; it is not an application runtime dependency. No media tools are downloaded by the running application. Acquisition is an explicit developer/build operation:

```powershell
pwsh ./build/acquire-tools.ps1 -RuntimeIdentifier win-x64 -Destination ./tools
dotnet restore --locked-mode
dotnet build --configuration Release --no-restore
```

Use `linux-x64` on Linux. Place the acquired `tools` directory beside the built entry point before a development run. `TRACKTRIM_TOOL_DIRECTORY` is a test setting; the desktop application always uses its app-local bundle. A portable package supplies this layout automatically.

```powershell
Copy-Item -LiteralPath ./tools -Destination ./src/TrackTrim.Desktop/bin/Release/net10.0 -Recurse
dotnet run --project src/TrackTrim.Desktop --configuration Release --no-build
dotnet format --verify-no-changes --no-restore
dotnet test --configuration Release --no-build --no-restore
```

See [CONTRIBUTING](CONTRIBUTING.md) for mandatory real-media checks and [fixture provenance](tests/TrackTrim.Infrastructure.Tests/Fixtures/README.md) for the generated VP8/PCM/SRT and checked-in direct FFmpeg-origin H264/AAC/SRT samples. The production archive contains the pinned FFmpeg/ffprobe pair for MP4. Fixture encoding is development-only; production uses explicit stream copy. Unit tests and headless UI tests do not replace a real desktop or a packaged workflow.

## Portable archives

```powershell
pwsh ./build/package.ps1 -RuntimeIdentifier win-x64
pwsh ./build/package.ps1 -RuntimeIdentifier linux-x64
```

Run each command on its target OS. The outputs are `artifacts/TrackTrim-win-x64.zip` and `artifacts/TrackTrim-linux-x64.tar.gz`. Each contains the complete self-contained runtime, tool dependency closure, license inventory, provenance, and an empty app-local `data` directory. Publishing is untrimmed, with no AOT or single-file optimization. Runtime security updates require rebuilding the archives.

Linux packaging extracts a pinned upstream MKVToolNix AppImage **at build time**. The application launches its extracted native CLI executables directly, with an app-relative library path in the child environment; it does not run media through a shell. Build-time acquisition/fixture helpers may use fixed wrappers. No FUSE, extraction, or download is required at first launch. Native dependency checks must pass during packaging; this is not a guarantee for arbitrary Linux distributions.

Windows packaging uses a verified source build of the same MKVToolNix 102.0 CLI pair, with its actual DLL closure and complete matched source/build materials. The build runs on an ephemeral Windows runner; an identified build can be reused locally without installing compilers. Provide `-WindowsMkvBuildDirectory` (or `TRACKTRIM_WINDOWS_MKV_BUILD_DIRECTORY`) as described in [CONTRIBUTING](CONTRIBUTING.md#explicit-media-tool-acquisition). Missing or changed workers/materials fail acquisition; official Windows binaries are not a fallback. This changes the worker distribution arrangement, not the MKV preservation contract.

Declared acceptance targets remain Windows 11 x64 25H2 and Ubuntu 24.04 x64 Desktop using X11/XWayland. Exact tested hosts and unverified desktop checks are recorded in [PLAN](docs/PLAN.md). See [native requirements](docs/SUPPORTED_FORMATS.md#platform-and-native-requirements) before making a compatibility claim.

The `62713d8` Windows candidate has [consolidated native functional evidence](docs/verification/release-candidate-evidence.json) on Windows 10: owner-assisted pickers, single MKV/MP4, mixed recursive plans/rules/presets and explicit queue Restore/Discard. Independent checks matched fourteen retained stream payloads across four GUI outputs and confirmed unchanged sources. UIA functional evidence does not establish visual layout, effective scaling or acceptance on the declared desktop targets.

To test a relocated archive, provide a generated multi-track fixture:

```powershell
pwsh ./build/verify-package.ps1 -ArchivePath ./artifacts/TrackTrim-win-x64.zip -FixturePath ./artifacts/fixtures/ordinary.mkv -Mp4FixturePath ./artifacts/fixtures/mp4/ordinary.mp4
```

This runs the actual packaged entry point from an unrelated working directory, tests a path containing spaces/Cyrillic/metacharacters, performs the real application workflow, and hashes the source before/after. It does not establish native dialogs, scaling, or clean-machine desktop acceptance.

Linux CI also verifies the actual workflow in a pinned Ubuntu 24.04 container with native OS libraries, no installed SDK/runtime/media commands, no network, and a non-root runtime user. Run it with `bash ./build/verify-clean-linux.sh ./artifacts/TrackTrim-linux-x64.tar.gz ./artifacts/fixtures/ordinary.mkv ./artifacts/fixtures/mp4/ordinary.mp4`. The successful check records the exact base image, installed package versions, user, and ASCII parent locale (`C`); the native worker boundary handles Cyrillic paths independently. See [PLAN](docs/PLAN.md) for executed evidence; a container CLI check is separate from Ubuntu Desktop acceptance.

Settings, bounded logs, and temporary-output ownership records are stored in `data` relative to the executable. An unwritable data directory is an error for media writes; the application must not silently redirect to a user profile. Startup recovery offers validated owned-temporary cleanup, never automatic publication or byte resume. Malformed, incomplete or nonregular records remain visible for manual review; they cannot authorize cleanup, and their original files remain untouched.
